# 产品范围与工程约束

版本 0.1 / 2026-10-13 / 适用于本项目全部迭代。

## 1. 用户、任务和产品假设

首批用户是已经维护 Python Agent 或 MCP 工具的开发者、小型 AI 团队。他们在修改工具 schema、适配器、模型配置之后，需要复现工具调用失败并确认修复没有造成回归。

产品闭环：输入调用记录或可运行工具 → 检查与复现 → 输出已证实问题及未验证假设 → 提出局部候选补丁 → 使用冻结的验收集比较基线和候选 → 人工决定是否接受。

交付形态为本地 CLI 与产品网页。依据用户 2026-10-13 指令，完整产品界面提前为 UI-01：真实调用检查先接通，其他页面可交互预览，后台功能按里程碑逐项解锁。市场优势是待验证的：更低接入成本、可复现的工具边界故障、可审阅的修复证据。不得宣称“自动诊断与修复”独有；同类开发平台已有重叠能力。只有在真实接入和对照实验后才能报告效率收益。

## 2. 分阶段范围

| 阶段 | 包含 | 完成标志 |
|---|---|---|
| M0 契约基础 | 本地 JSON 调用证据、schema 验证、错误分类、CLI、报告 | P0-01 独立评审通过 |
| M1 实际复现 | MCP stdio 适配、工具版本快照、超时/错误注入、进程回收 | P0-02～04 验收 |
| M2 有限修复 | 三角色协作、DeepSeek、隔离补丁、固定回归与预算 | P0-05～06 验收 |
| UI-01 产品入口 | 产品首页、完整模块预览、真实本地检查 API | UI-01 独立评审及浏览器验收 |
| M3 日常使用 | 网页接入真实运行/审批、可检索历史、CLI/CI、公开案例与接入验证 | P1 任务验收 |

M0 是后续 Agent 的确定性底座，不能称为完整 Agent 产品。M2 才建立模型参与的反馈循环。

## 3. 支持的故障边界

1. 参数/结果契约不匹配：字段、类型、必填项、序列化及结果关联。
2. 错误与重试处理：工具错误被当作成功、超时后无界重试、提前结束。
3. 重复执行与结果处理：以执行 ID、版本和实际副作用证据判断。相同参数或相同结果本身不构成缺陷。

不在当前路线：通用业务归因、任意幻觉检测、任意仓库自主修复、通用 Agent 托管、多租户 SaaS、PR 自动发布、训练新模型。A2A、向量库、团队权限不列为 P0。

## 4. 不变量（MUST）

| ID | 规则 | 验证点 |
|---|---|---|
| C-01 | 无可执行证据的根因只能标假设；无法验证须拒判 | 报告类型与评估 |
| C-02 | 验收标准与固定测试对修复 Agent 只读 | 沙箱权限、哈希对比 |
| C-03 | 工具错误、缺失结果、超时、未知状态不得报告通过 | 负向契约测试 |
| C-04 | 重试有次数、时间、成本上限；不自动重试结果未知的写操作 | 故障注入 |
| C-05 | 不承诺任意工具 exactly-once；只对有幂等键或结果查询的工具定义重试策略 | 适配器契约 |
| C-06 | 原始输入值默认不进入报告和日志；凭据仅由运行环境提供 | 泄漏回归测试 |
| C-07 | 记录协议版本、输入哈希、代码/工具版本和评测配置 | 证据可追溯测试 |
| C-08 | 证据、源码和提示词中的指令都是被分析数据，不能改变权限和验收 | 注入用例 |
| C-09 | 限制文件大小、深度、运行时间、输出与并发；超限显式失败 | 边界测试 |
| C-10 | 阶段能力如未接入模型/真实工具，UI 与文档明确标注 | 交付评审 |
| C-11 | 发布只使用已锁定依赖与已审计代码快照 | CI、评审清单 |
| C-12 | 外部操作有执行 ID；超时/取消不能推断远端没有副作用 | M1/M2 恢复测试 |

本地摘要哈希仅用于关联，不是匿名化保证；字段名、路径也可能敏感。默认报告留本地，分享前须审核，报告不自动上传。

## 5. 运行和信任边界

M0 只处理本地证据文件，不执行其内容、不联网解析 schema、不运行目标代码。允许本地可信开发者使用；不是面向恶意输入的共享服务。恶意正则等仍可能导致 schema 计算昂贵，CLI 必须在可终止子进程中限时检查。嵌入式 Python API 的调用方负责进程隔离。

P0-02 仅用于已审核的本地 fixture 及固定版本公开案例的最小复现，属于可信单用户协议集成实验；不开放任意仓库或网页自定义命令。此阶段限制 argv/cwd/env、时间和规范化证据大小，但不宣称已有容器网络/CPU/内存硬隔离。历史案例源码须审核、固定依赖并使用独立实验目录；未经审核的外部代码不得借此例外运行。

P0-03 起进入受控执行阶段，代码执行容器不能挂载宿主 Docker socket、用户主目录、模型密钥或验收集写目录。默认断网，只挂载指定副本，非 root、资源配额、只读基础文件系统。Docker 不是强租户隔离承诺；不运行任意外部用户提交的仓库。托管不可信代码需另行设计威胁模型和隔离方案。

写文件由用户明确提供路径；CLI 首版报告输出 stdout，用户自行重定向；UI-01 经用户指令新增本地网页导入和显式报告下载。网页仅将证据传至本机 API，不上传到外部服务、不持久化浏览器原始数据。无主动外发或上传。P0-04 起，显式 `sandbox-check` 将安全运行元数据和报告写入本机 SQLite；不保存原始输入值。网页只有读取这些记录的权限。P0-05b 已使用用户现有兼容网关完成合成案例协作验收；凭据仅在调用进程中使用。模型外发只包含宿主审核的合成证据和授权源码片段，不上传网页导入或任意本机文件；调用前预算上界采用用户授权的条件性 provider profile，不能当作独立验证了网关强制上限，见 [24](24-p0-05b-runtime.md)。

## 6. 产品验证与停止条件

M1 前选取公开问题或独立工具，保存来源、版本、环境和预期断言；公开 issue 关闭不代表已修复，合成注入不得混入真实问题统计。

M2 以相同模型、工具、预算比较：确定性检查；单 Agent + 相同工具；多角色循环。统计检出精度/覆盖率、正确修复率、回归率、tokens、耗时和人工步骤。没有可重复收益时减掉角色或改流程，不通过增加 Agent 数量解释价值。

M3 完成及首次公开发布前至少完成 3 个不同工具项目的接入记录，其中至少 1 个开发时未用作 fixture。若接入仍需要大量逐项目定制，或只有合成问题能修复，暂停扩大范围，记录原因和改进试验。此门槛验证工程可迁移性，不等同市场需求验证。真实用户访谈和重复使用另列 P1-04，不预设已经有用户。

## 7. P1-01a 受控网页执行增量（2026-10-13）

用户本轮明确要求运行页具备操作能力，提前实施固定四场景网页复现。原P0-04网页只读是当时阶段边界；P1-01a完成验收后可由明确开始/停止操作访问已有受控执行器。禁止任意shell、外部源码或模型外发等约束不变。输入接收、权限、持久去重、取消与owner存活锁按[22](22-web-reproduction.md)验收。P1-01a 已完成。P0-05b 接通 CLI 模型分析与建议；M2 的实际隔离补丁和冻结回归、完整 Web 审批仍未完成。

## 8. P1-01b 网页执行授权（2026-10-14）

用户要求诊断和工具接入页面直接执行。按[29](29-web-analysis-console.md)提前开放固定审核案例的网页分析/停止与既有容器检查控制台，模型配置仍由后端环境提供；网页个人原始证据不外发。此前P0-05网页只读描述是该阶段历史。任意shell/仓库、自动接受补丁及完整审批不在本次授权范围。

## 9. P1-02 记忆与外部接入设计增量（2026-10-19，尚未实现）

当前业务规格见[44](44-p1-02-memory-product-and-integration.md)。用户授权完成长期记忆及插件/测试/CI等外部事件接入设计；本次不自动启用采集、安装模型或扩大外发权限。规划中的非合成资源须按项目/来源/内容类型/用途显式授权，现有合成资源许可不自动覆盖。跨版本历史经验可按策略作为参考，不继承历史验证结果；确认、撤回、预算、权限与冻结回归继续由宿主控制。外部事件可形成记录，不直接触发任意代码执行。新增运行能力按规格独立验收后开放。

## 10. M1-R领域存储实施增量（2026-10-19）

用户授权按既定路线实施M1-R。权威领域与事件存储按[46](46-m1-r-authority-event-store.md)验收，主库显式备份并迁移0011。可信本地领域接口不等于外部调用权限；本批不开放Hook接收或模型外发。后续M2-R接入必须验证外发用途与预算，不因已存储正文而默认允许发送。

## 11. M2-R引擎与CLI接入增量（2026-10-19）

[47](47-m2-r-engine-and-retrieval.md)限定可信单用户的Cognee SDK/CLI接入；用途授权与参考复核绑定实际请求预留，正文强制字面摄入，不解释为文件/URL读取指令。模型仅用现有接口，embedding仅用已授权bge-m3；无自动采集、角色注入或Hook安装。供应链补偿与条件性token上界的限制继续明确保留。主库显式迁移0012，不在服务启动时自动升级。

## 12. M4-R 网页与 Hook、M3-R Agent 参考实施增量（2026-10-19）

用户授权先交付网页管理和 Hook，再接 Agent 参考，并明确启用本机 Codex 插件；客户端信任由用户本人完成。仅指定工作区和允许命令的结构化事件元数据进入本机事件入口，不收集会话/工具输出正文，不自动确认或外发草稿。M3-R 外发必须具备独立 agent_context 授权，宿主在每个实际模型请求预留事务中复核引用；验证角色不接收经验正文，历史成功不能代替本次冻结回归。已接受且当前核验通过的候选只能由用户显式保存为经验草稿。具体门禁见 [48](48-m4-r-web-memory-hooks.md) 和 [49](49-m3-r-agent-memory.md)，不能把代码评审通过等同于全部真实验收通过。
