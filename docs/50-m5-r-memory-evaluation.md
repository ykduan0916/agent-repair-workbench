## 1. 研究问题与范围

保持模型、角色、工具和冻结回归相同，加入已确认经验是否改变修复通过率、工具调用量、token 消耗和耗时？错误经验是否导致错误候选被误判通过？

本批只评估两个已审核合成案例的**同版本、人工提示消融**。正确/错误经验由宿主预先编写，包含公开契约建议，不含完整补丁、隐藏断言或评测期输出。它不是历史学习泛化，也不代表用户项目成功率。小样本结果不能证明商业收益。

M5-R 的跨版本相关/不相关来源、独立工具项目效果评估仍未完成；本批结束不自动将父里程碑标为 done。外部 Hook 的真实触发证据沿用 48，不计入本批修复样本。

## 2. 调用前冻结的协议

- 案例：`output_mismatch`、`counter_offset`。
- 处理组：none（不接记忆）、correct（正确契约建议）、wrong（反向错误建议）。每个案例每组重复两次，共 12 个计划单元。
- 第一块按案例及 none/correct/wrong 顺序执行；第二块反转案例及组顺序。顺序预先固定，不根据结果选择。
- 四份经验分别放在四个独立权威库/引擎目录，同一份索引只复用两次。两个无记忆库没有经验；每个任务独立快照及账本。任务完成不生成新经验、不修改已确认经验。
- 同一既有 DeepSeek 兼容模型、三角色、同一提示词/工具/镜像/冻结回归。已有 bge-m3 只用于记忆组。服务端模型版本、采样随机性和缓存不能完全锁定，记录为实验限制。
- **每组 Agent 预算完全相同**：1,900,000 tokens、12 次模型、20 次工具、2 个候选、600 秒、单次输出 8192。每组统一预留额外 100,000 tokens 给检索，无记忆组不消费该份额。实际记忆请求仍受生产层 6 次 LLM/40 次 embedding 等限制。
- 调用生产 `RepairController`/Cognee/真实 Docker，走隔离 CLI 执行；不改产品 API 的预算策略，不宣称新增网页操作验收。
- 索引为独立准备费用：每份只允许一次索引，180 秒；其失败、未知用量全部保留，两次依赖任务计 setup_blocked。每个修复任务只启动一次，外层 780 秒收尾上限，不重放未知写操作。
- 执行前保存 plan.json：全部任务 ID/顺序、Agent 预算、代码/模型配置/embedding/镜像/案例/建议正文/冻结 oracle 摘要。中途代码或配置变化停止；不能把修复后的成功拼进旧实验。
- 每个结果单独落盘；索引失败、no_match、unknown、模型拒判、超时、未启动都保留于原计划分母。资源回收不确定或安全不变量破坏立即停止余下单元，明确记 not_run_safety_stop。

运行命令（显式真实模型调用）：

```bash
uv run --frozen python ops/m5r_eval.py --execute
```

退出码0只表示整组计划已记录完毕（可能全部准备失败），不代表记忆效果门禁通过；结论必须读取summary及逐项状态。

读取已有私有模型/embedding 配置，不下载模型。产物为 `artifacts/m5r/<study-id>/`，目录 0700、文件 0600；主运行库和用户记忆不受影响。调用日志不输出正文、参数、凭据、provider 异常。已有任务文件拒绝重放；意外中断需先检查原 ledger 与容器，不得删除旧目录重跑冒充续跑。

## 3. 判定与统计

1. 主指标：每组通过数 / **计划 4 次**。只有任务 outcome 与当前重验的冻结比较均为 candidate_verified 才算通过；模型宣称成功不算。
2. 暴露率另报：逐请求引用审计证明 diagnosis/repair 实际收到经验；无匹配仍属于原组。verification 必须没有经验正文引用。
3. 回归：同一比较 baseline-good 通过而 candidate-good 失败。基础设施 unknown、baseline 不通过单列，不能混为回归。
4. 每次列出模型/工具调用、候选数、实际 token、保留量、耗时。缺失用量写 unknown，已知 token 只是下界；没有单价就不虚构金额。
5. 总费用 = 全部索引一次 + 全部检索 + 全部 Agent 调用，失败也计入。冷启动费用单列；索引按固定两次计划使用摊销仅作补充，不能在总计里重复加索引。
6. 成功/失败按相同案例、重复号配对展示；只作描述性结果，不报显著性、不宣称通用提升。固定自动执行流程没有测量用户人工时间，不宣称节省人工步骤。
7. 冻结测试拒绝错误补丁是系统安全性，不能把错误记忆未产生收益包装成记忆有效。
