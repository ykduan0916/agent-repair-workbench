# UI-09：记忆模块与 Hook 来源管理

2026-10-21。Feature P1。状态 done（planned → ready → in_progress → in_review → done）。依据用户明确要求及 44 的记忆业务设计，修正 M4-R 把事件管理放入环境配置的页面归属。

## 产品结构

- 工作区主导航“记忆”：`/workspace/memory` 为记忆库，`/workspace/memory/hooks` 为 Hook 与事件。
- 两页共用紧凑子导航，携带所选项目；Hook 子页仍激活主导航的记忆入口。
- 记忆库保留类型/状态/工具筛选、来源、确认、编辑、撤回和适用策略。
- Hook 与事件直接展示来源、接收是否启用、凭据是否有效及当前页事件，分别显示接收、处理和生成记录。管理凭据、下载私有配置、连通测试、暂停、授权和索引维护沿用既有操作。
- “最近事件”默认可见；凭据和低频管理继续按需展开。事件链接使用“查看记忆记录”，不将可能已确认的记录一律称为草稿。
- 环境与接入保留运行环境、模型、存储、角色/工具接口和本机命令。旧 `#memory` 入口替换跳转到记忆 Hook 页面，只保留 project 查询参数，不把任意 URL 当作跳转地址。

## 能力与事实边界

该批调整信息架构，不新增 Hook 事件类型、采集白名单或模型调用。来源启用/凭据有效不等于 Codex 客户端在线或已信任；本页事件数量不是来源全历史总数。浏览与切换只读，不自动测试连接、生成凭据、确认经验或外发正文。原有 Codex Hook 实际触发证据仍见 48。

图谱探索、自动经验合并、项目级共享图均未借此标为已实现；M5 向量接口失败仍是独立阻塞。
